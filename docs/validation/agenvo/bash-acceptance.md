# Windows Git Bash acceptance

Use [bash-vectors.json](bash-vectors.json). These commands were generated by the
actual `bashCommand` function; source hashes are recorded in the JSON. Their
presence alone is preparation evidence; the separate [Windows result record](README.md#real-windows-wrapper-acceptance)
describes the completed runtime-side observations. The older PowerShell vectors
are superseded and must not be run.

This batch uses new `200...` nonces and explicit CRLF around every completion
frame. The first `100...` vector on Windows produced the expected output and
exit 0 inside its payload, but terminal residue `U+01B0 U+006D` preceded the
frame on the same line. Strict parsing did not accept it. That attempt remains
unknown; do not resend it or count payload inspection as a successful result.

The existing Windows execution thread verified Git Bash 5.2.26(1)-release,
`OSTYPE=msys`, UTF-8, native Windows process exit/stderr, and `cygpath` in a
one-time process. It also found that PATH's first `bash.exe` is a WSL launcher.
The application therefore requires the verified **absolute Git Bash path** in
the account target's `bash_path`; no PATH fallback or WSL is used. The real
path belongs only in local configuration, never in this repository.

## Minimal execution

1. Reuse the authorized Agenvo device/instance and observed Herdr session.
   Reuse the still-live acceptance workspace and pane already observed by the
   runtime thread after the first Bash attempt. Do not create another workspace
   for this batch. Do not resume saved IDs after a Herdr restart or uncertain
   lifecycle. Inspect uncertain attempts instead of repeating a create or run.
2. In each JSON `pane_run_command`, replace the **one occurrence** of the
   `bash_path_parameter` value with the already verified Git Bash path. The
   path is a PowerShell single-quoted argument: replace any literal `'` in the
   real path with `''`. Change nothing in the encoded script. This is local
   parameter substitution, not local development. The template hash changes
   after that substitution; do not publish the private substituted command.
3. Submit each vector exactly once, sequentially, via native `pane.run` with
   the recorded `session`, `paneId` and complete command. PowerShell only
   launches Bash; it never evaluates the user body. No launcher command exits
   the interactive pane or changes its shell/profile. The Bash body is a
   separate `--noprofile --norc -p -c` process with empty stdin. `-p` also prevents
   importing `BASH_ENV` and shell functions.
4. Read the same pane using `lines: 500`, `source: "recent-unwrapped"`. Decode
   MCP text to the receipt, then use **`result.output`**. `accepted` means
   submitted only. Poll reads at most every 500 ms for at most 30 seconds;
   never resend a command after an unknown result.
5. For the delayed vector, attempt a read in the first two seconds. If latency
   exceeded its eight-second sleep, record the early assertion as not observed.
   Stop waiting and record **unknown**, no exit code, workspace retained. Do
   not send Ctrl-C, kill, close or resubmit. A later read after ten seconds may
   record late completion separately; it does not change the canceled request
   into success. Cloud canceled-context tests separately verify adapter state.
6. Keep the single acceptance workspace for review. Do not automatically close
   it; no atomic generation guard exists. If Herdr restarts or lifecycle
   identity becomes uncertain, do not resume from saved IDs.

These steps reuse one pane only for manual wrapper validation. Application
execution still allocates a new workspace for every command, with per-Bot
authorization checked before every native call.

## Assertions

| Vector | Required result |
| --- | --- |
| Normal/Unicode/native/path | Bash 5.2.26, msys, result 42 and Chinese/✓; native `cmd.exe` prints `Windows_NT`; private cwd survives a `cygpath` round trip, only an OK marker is printed. Exit 0. |
| Native stderr | Both `MEMOH_STDERR` and `MEMOH_AFTER`, in order; exit 0. Diagnostic output must not abort the Bash body. |
| Native nonzero | `MEMOH_NONZERO` and exit **7** from native `cmd.exe`. |
| Large output | Exactly 4096 output bytes: the 12-byte `MEMOH_LARGE\|` prefix and 4084 `x`; truncated true, exit 0. Excess output is drained to avoid SIGPIPE. |
| Delayed observation | Echo alone is not completion. Cancellation remains unknown; a later frame can contain `MEMOH_DELAYED\|42` and exit 0. |

The normal vector sets `MSYS2_ARG_CONV_EXCL='*'` only on its native `cmd.exe`
invocation to preserve Windows switches. It does not set global environment or
print private paths. Mixed native CRLF and Bash LF are expected; retain exact
decoded output and apply the JSON's contains/order checks where specified.

## Completion format

Accept one entire trimmed line:

```text
MEMOH_<nonce>:<base64 UTF-8 JSON>:END_<nonce>
```

The JSON contains `output_base64`, integer `exit_code` from 0 through 255, and
`truncated`. Decode `output_base64` to UTF-8 text, at most 4096 bytes. On
truncation only, an incomplete final UTF-8 character may be omitted. Binary/NUL
or malformed text is unsupported. A missing/null exit code is never success.
Known `failure` frames (`bash_unavailable`, `unsupported_bash_host`,
`bash_tools_unavailable`) have no exit code and are explicit rejection.

Normalize snapshot CRLF to LF, trim each line, and match only this vector's
nonce. Ignore other vectors' frames. Multiple matching frames in **one**
snapshot, invalid base64/JSON, oversized payloads or invalid output are unknown.
Parse each snapshot independently; do not concatenate repeated reads. Never
inject a synthetic result into the terminal.

The wrapper writes CRLF before the frame and after its suffix, including known
failure frames. Residual terminal text belongs on the preceding line. Do not
strip arbitrary prefixes, search for frame substrings, or treat an echoed
launcher as completion. Business output stays inside the base64 payload, even
when it prints a frame-shaped string. Confirm this physical line boundary in
the real snapshot before recording a pass.

Return per-vector submission count, request ID, parsed output/exit/truncation,
early-read observation and any close/termination count (expected zero). Keep
private target IDs, paths, prompts and unrelated terminal history in the private
execution thread. No new credentials, shells, services or global settings are
required. This protocol check is not a full runtime replacement or proof of OS
isolation between authorized Bots.
