# Windows PowerShell 5.1 wrapper acceptance

These are **unexecuted Windows test vectors**, not successful Windows results.
Run them through the existing authorized Agenvo/Herdr connection. No Memoh
checkout, development source, new credentials, agent install or production
configuration is needed on Windows. The commands only calculate, print, sleep
and start `cmd.exe` to return a nonzero code; they do not write files or use the
network.

## Exact source and commands

[windows-vectors.json](windows-vectors.json) contains four complete
`pane_run_command` strings generated by calling the actual `powershellCommand`
function from commit `bfd838754763cae87d3d71abedd06b24a9e0bec8`. The source
`internal/agenvo/exec.go` is byte-identical to the independently reviewed commit
`cc29415989cf6f6be3f0a89cd878ab490c0f04ad`; its SHA-256 is
`0ec7c4bc519b2298bfb9aa50685e88343298fab41a70415883b85b918cc11902`.

A temporary Go test overlay called the real generator and `parseCompletion`
without changing application source. The exporter verified that an echoed
encoded command does not contain a literal completion prefix and is not parsed
as completion. It also checked each **synthetic** expected frame through the
actual parser. This is preparation evidence, not execution evidence.

Use `pane_run_command` verbatim as JSON string data in `pane.run.command`.
Do not reconstruct, decode/re-encode, or run the `body` field directly. Never
execute or inject `synthetic_example_frame`: it exists only to explain the
expected parser input. `command_sha256` hashes the exact UTF-8 command with no
trailing newline. Fixed nonces are solely for this one-time manual acceptance;
production uses fresh random nonces.

| `nonzero_exit` | `MEMOH_NONZERO\|42` followed by CRLF | 7 | false |

| `delayed_observation` | No completion before the eight-second sleep finishes; later `MEMOH_DELAYED\|42` followed by CRLF | 0, only in a later observed frame | false |

from the synthetic example. Compare the **decoded fields**, not the whole frame
string. PowerShell 7 output does not satisfy the first vector: the subprocess
must report Windows PowerShell `Desktop|5.1`.

## Minimal native operations

1. Reuse the already authorized device/instance and observed Herdr session. If
   an earlier acceptance attempt exists, inspect its recorded outcome first;
   never repeat a `workspace.create` or `pane.run` whose outcome is unknown.
   Use one newly created, uniquely labeled acceptance workspace with an
   existing, approved working directory. Record the create receipt's
   `result.result.workspace.workspace_id` and
   `result.result.root_pane.pane_id`. Do not guess IDs or recover an old ID after
   a Herdr restart. If the lifecycle is uncertain, stop this attempt.
2. In that continuously observed workspace, submit each of the first three
   vectors **once**, sequentially, using:

   ```json
   {"session":"<observed-session>","paneId":"<fresh-root-pane>","command":"<exact pane_run_command value>"}
   ```

   The existing MCP `execute` uses the unchanged native call shape
   `return await call({deviceId, instanceId}, "pane.run", params);`, with every
   argument JSON-encoded as data. `execution: accepted` means submitted only.
   Read the same pane with the adapter's actual parameters:

   ```json
   {"session":"<observed-session>","paneId":"<fresh-root-pane>","lines":500,"source":"recent-unwrapped"}
   ```

   Poll read-only as needed, at most every 500 ms, for up to 30 seconds. Parse
   the current snapshot as described below. Keep each submission's request ID,
   count and result separate. Read retries never authorize command resubmission.
   Reusing this one pane is only for the manual wrapper contract check; the
   application executor still allocates a fresh workspace per operation.
3. Submit `delayed_observation` once and attempt an early read within the first
   two seconds. The command echo, idle prompt or PSReadLine diagnostic must not
   produce completion. If transport latency already exceeded eight seconds,
   mark the early-read assertion **not observed**, rather than rerunning it.
4. Stop waiting after that early read. Record `state: unknown`, no exit code,
   `cleanup_required: true`. This is cancellation of observation, **not proof
   of process termination**. Do not send Ctrl-C, kill or close. A single later
   read after at least ten seconds may observe completion of the same command;
   keep it as a late observation and do not retroactively turn the canceled
   request into success. The cloud `TestExecuteCancellationRetainsUncertainWorkspace`
   separately verifies the adapter's canceled-context state mapping. Manual
   Windows observation alone does not exercise that Go context path.
5. Retain this acceptance workspace and its known outcome for operator review.
   Do not automatically call `workspace.close`, including after success. There
   is no atomic generation guard; label/get/list checks cannot make closing a
   potentially reused ID safe. No other workspace should be touched.

## Exact parser contract

Decode the MCP text content into its native receipt. `pane.read` terminal text
is **`receipt.result.output`**, not `receipt.result.result.output`.

For each current snapshot, normalize CRLF to LF, split lines and trim each
line. Accept only a complete line starting `MEMOH_<this-vector-nonce>:` and
ending `:END_<this-vector-nonce>`. Decode the middle as standard base64 and UTF-8
JSON. The result must contain an integer `exit_code`; compare `output` and
`truncated` with this vector's expected fields. No matching line means pending;
it is not an exit code of zero. Ignore markers belonging to the other vectors.

The actual parser rejects malformed base64/JSON, absent/null exit codes,
encoded payloads over 32768 characters, decoded output over 16384 UTF-8 bytes,
and **multiple matching frames within one snapshot** as unknown. Do not append
successive snapshots and then parse them as one: the same frame can naturally
appear in multiple reads. The wrapper bounds output to 4096 UTF-16 code units;
the large-output vector uses ASCII to make its expected length unambiguous.

Return per-vector submission count, request ID, observed PowerShell version,
parsed output/exit/truncation, whether an early echo-only snapshot was actually
captured, and whether any automatic close/termination occurred (expected zero).
Keep raw receipts and local identities in the private execution thread. Only
the synthetic frame and decoded synthetic output may be copied to the public
PR; redact prompts, working directories, device/instance/session/pane IDs and
any unrelated terminal history. Do not rerun an already submitted vector to
obtain cleaner evidence.
