# Isolated verification evidence

All users, profiles, Runtime records and transfer credentials in these checks are synthetic. No production credential, real enrollment, TLS bypass or deployment was performed.

- `verification-summary.json`: current Go/Vite application, isolated PostgreSQL/pgvector, 23 HTTP and identity checks, five data-preservation invariants, process restart and actual Chromium UI checks. The required development stack was run with equivalent commands because mise was unavailable.
- `api-results-final.json`: owner/foreign/pending/revoked/profile/admission checks with expected HTTP status and public error codes, plus identical PUT/GET native identity and full identity/fingerprint readback after a separate server process restart before any profile write.
- `source-after-final.json`: source file hashes used to verify the running binary was built from the final implementation; root rechecked all entries with zero mismatches before committing.
- `native-computers.png`: the synthetic Windows registry row remains correctly offline; no live device was simulated in this UI.
- `native-access-granted.png`: the existing Bot-access control was toggled in the real UI and verified again after server restart.
- `postgres-results.json`: isolated migration, admission concurrency, RLS, config CAS, transfer lifecycle and durable producer delivery regression results. Tests create their own databases from `TEST_POSTGRES_DSN` with `go test -tags=integration ./internal/db` and require no external PC.
- The cutover integration result also verifies the existing inactive-connection setting stops old automatic OAuth paths without changing historical workdir/session bindings; see [the cutover procedure](../../native-runtime-cutover.md).
- Official CLI evidence is in `internal/nativeherdr/testdata/herdr-v0.9.5.json`; repeat with `scripts/probe-herdr-contract.py` and the pinned official Linux binary.

Affected package tests and race checks passed for nativeherdr, agenvo, computertask, userruntime, workspace/bridge, containerfs/fallback and core. Swagger/sqlc/SDK generation, SDK typecheck, changed-scope golangci-lint 2.10.1 and whitespace checks passed.

Full handlers race verification subsequently passed three complete repetitions on both 9601 and the candidate working tree: `go test -race ./internal/handlers -count=3`. The earlier three failures cannot be assigned a unique cause from their retained logs. Controlled, temporary Go overlays reproduced the same pre-existing short-heartbeat-budget sensitivity on both versions: a 200 ms scheduling pause makes the 150 ms heartbeat expire before the 600 ms terminal idle timer. A test-budget-only overlay passed that same pause while the separate heartbeat controls still passed. No repository implementation or test was changed for this diagnosis, no test was manually skipped, and no data-race report occurred. [Diagnostic evidence and exact commands](terminal-race-diagnosis.json) distinguish these observations from the unproven cause of the earlier failures; a final full `go test -race ./internal/handlers -count=1` also passed in 13.347 s after the identity/SDK changes. The cutover integration test and documentation were added after the UI capture; they do not change the running implementation.
