# Optional native input session contract

This is a source candidate on the frozen e57d218b → ba44c062 baseline plus the independent settled-cursor P1 fix7a1784ce. It is not installed, deployed or accepted for a production provider. [The minimum current-provider projection](SAFE_FIELDS.md) is still required from the unique writer. No actual provider, voice, model or ASR request was made in this work.

## Protocol selection and source basis

Twilight's normal speech interface and all fixed-text methods remain unchanged. The existing registry explicitly declares `alibabacloud-speech` as CosyVoice run-task/continue-task/finish-task. Only its existing factory returns a wrapper with the optional `input.Provider` interface; the wrapper embeds/delegates the original Twilight provider for fixed synthesis, streaming and discovery. Model/voice names do not activate this capability. The configured model and effective voice/options are used; no new model or voice ID, provider, service or Agent core is introduced.

Both the pinned Twilight `v0.7.2-0.20261002230120-f6d0ce1a0e8c` and released `v0.9.0` (origin`0ee7c270912f58f3b9d21ec1430366e106c5139c`) were read through normal Go module tooling. Public SpeechParams still exposes one Text string; private CosyVoice WS sends one continue then finish. No dependency upgrade was made. The actual fixed-interface WS negative control produces two tasks for two inputs; the new session produces one task with multiple continue commands.

Primary bases:

- [CosyVoice official client events](https://www.alibabacloud.com/help/en/model-studio/cosyvoice-client-events), read2026-10-30: wait task-started, send multiple continue-task with one task_id, then finish and drain through task-finished. SSML permits only one continue. Native limits are20,000 characters per frame and200,000 per task; this adapter enforces Unicode-code-point counts rather than truncation. Input inactivity can exceed the documented23-second limit and fail; no fabricated speech/space heartbeat or paid retry is added.
- [Pipecat v1.14.0 aggregator](https://github.com/pipecat-ai/pipecat/blob/v1.14.0/src/pipecat/utils/text/simple_text_aggregator.py) and [sequencer](https://github.com/pipecat-ai/pipecat/blob/v1.14.0/src/pipecat/utils/context/aggregated_frame_sequencer.py): distinguish accumulated source/visible text, actual synthesis input, order, completion and interruption. Retain conservative semantic aggregation; complete units now append into one provider context instead of independent synthesis contexts. No overlap text is read twice.
- The previous fixed-source design's [LiveKit/MSE/Howler sources](../continuity-20261030/CURRENT.md) still apply to textual lookahead, native serialized append and stop-vs-unload cache lifetime. Encoded output remains on one native decoder/clock; no new decoder or guessed crossfade is introduced.
- Installed `markstream-vue2.0.0` public `MarkstreamRendererHandle.getVirtualMetrics/settle` is used for actual source completion. Its `render-final` event is gated by virtualScroll in source; enabling virtualization would change the chat profile. The first actual-app attempt demonstrated that event-only waiting never finishes. The fix keeps the nonvirtual chat profile and reads public final/stable/rendered-count metrics, with renderer-owned settle where needed. No application quiet timer is invented. Source equality and connected-element checks reject stale completion; a reveal/typewriter catch-up pulse is not treated as final input.

The adapter uses the configured TLS WebSocket endpoint and normal certificate validation. Remote non-TLS URLs, userinfo, query and fragment are not native-input capabilities in this candidate; only explicit loopback WS fixtures are allowed without TLS. Such native-ineligible configurations retain their original fixed-text path before any native task is opened. No endpoint is inferred to be CosyVoice from a Qwen/model display name. Actual endpoint/protocol consistency remains a production-readback condition.

## Application transport and authorization

The existing service/handler carries the session; there is no new background service or client credential bridge. The shared generated SDK uses ordinary streaming HTTP and sequential PUTs, preserving current fetch/CORS/auth behavior. Browser duplex upload support is not assumed.

1. `GET /bots/{bot_id}/tts/playback/config` keeps its opaque effective identity and optionally adds `input_content_type`. The new service reads one resolved configuration snapshot; it does not open a native connection. Only explicit input-capable providers with valid config advertise input. Disabled providers and SSML do not. The client selects native input only for supported MP3 MSE. Other formats/platforms retain existing fixed-text behavior, which is not claimed naturally continuous. A missing legacy capability route404 may take the original fresh-reply path once because that GET generated nothing.401/403, network failure, malformed response or cancellation do not become a synthesis fallback. This fresh-reply compatibility rule does not apply to cached Replay.
2. `POST /bots/{bot_id}/tts/playback/input` starts one fresh row. Body: `{id, sequence:0, offset:0, text, final:false}`. ID is a securely generated UUID, text is nonempty. The server map is scoped to authenticated actor/Bot/ID. Start uses the same active-account JWT and Bot chat permission; chat_route credentials are rejected before account/Bot ownership logic. Duplicate active IDs do not open another native task. The native task is opened and first frame accepted, then HTTP200/audio/config-identity headers are flushed **before audio** so a provider waiting for more text cannot deadlock ingress.
3. `PUT` at the same path carries `{id, sequence, offset, text, final}`. Sequence advances by1; offset counts exact accepted Unicode code points, including preserved whitespace. Appends are serial. Every PUT rechecks the active account, Bot chat permission, configured model and effective configuration identity. Wrong sequence/offset is rejected, never replayed to the provider. Unknown/closed IDs return404; not-ready or changed config returns409. None creates another synthesis. Native ingress uses the documented20,000-character frame bound; the original fixed `/tts/playback`500-rune limit is unchanged.
4. The browser sends its last tail, waits for that append acknowledgement, then sends one empty final frame. Finish waits for response-final source plus actual renderer completion and all queued source spans. Final closes text input, not audio output. Provider binary frames continue until the matching task-finished. Foreign task IDs, early task-finished, failed tasks and unexpected close are errors. Internal config cancellation and any error after headers abort the HTTP body rather than yielding clean EOF, preventing truncated audio from becoming a complete cache entry.
5. Cancel aborts the shared main request and pending PUT, clears the playback queue, detaches player events and closes the upstream task connection. It does not assume the region/model-specific finish-cancel directive is supported. The body/context and generation fence prevent late responses from continuing or opening a new task. No uncertain append/start is retried. Transport disconnect cannot prove a provider's billing cessation; no such claim is made.

The server ID is an authenticated actor/Bot transport association, not authorization for a chat/run/episode. The existing client scope/run/message and workspace admission owners remain authoritative for UI selection. Native task IDs never authorize another account/Bot. No old auth route, legacy `/tts/synthesize`, Bot navigation or official Agent behavior is relaxed.

## Source coverage, cache and lifecycle

The existing visible renderer projection excludes hidden link targets, tool/status/reasoning output and explicit voice-file attachments. Stable render row ID identifies the active bubble; turn remains context, and explicit new run revisions stay distinct. P1 prerequisite7a1784ce uses the same observed revision for both cursor reads and writes after settled history omits runtimeRunId, preventing duplicate final-tail appends and cache-version corruption.

One native task receives the exact selected source spans in order. Source sequence/offset rejects duplicated or skipped submissions. The cache taps the consumed encoded stream with bounded provider channel/HTTP/native append backpressure; no faster unbounded tee is added. It captures the complete accepted source string at clean audio EOF, not at the initial request's first sentence. This proves submitted text/frame order and retained bytes for fixtures, not that a real voice uttered every word.

Completed cache remains bound to principal/Bot/session/model/turn/render-row/run, actual resolved voice/model/format identity, MIME and normalized visible text version. Replay validates current permission/config through the read-only GET, then plays the saved bytes. It submits zero start, append or fixed generation requests. A loaded blocked/paused operation's Continue uses the exact source and can finish only its original pending input. It is distinct from completed cached Replay.

Stop/input/click/visibility/scope/route/deactivation consumes the live reply and old queued work. Completed generated bytes survive Stop while this pane instance remains alive. Partial or uncertain bodies are explicitly unavailable. Returning to that surviving pane can manually replay complete bytes after validation; it never resumes the old queue automatically. Auth change/unmount clears page cache; reopening a destroyed pane has a missing cache and must not silently synthesize. No persistent history, attachments, user storage budget, TTL, new audio controls or management log panel is changed. No persisted cross-page audio restoration is claimed.

Existing single-bubble playing/paused/loading/end/error state and reduced-motion/accessibility styles remain. ArkWeb activation, MP3 MSE and foreground/background/native-back behavior remain actual-device acceptance conditions. No autoplay policy or TLS override was granted. The separate conversation-ack owner's status/episode protocol is not consumed; no second player was added.
