# Minimal field steps — sole writer only

This is a handoff, not an executed phone test. Every actual-device result starts
UNVERIFIED. Keep HC-03/05 source changes with their existing owner.

1. **Bind the observation to the actual installation.** Record the package's
   release-manifest digest/signature from the existing distribution record, then
   read the phone's installed application information for
   `cloud.begonia.workassistant`. Target source fcc39b31 corresponds to 1.0.34 /
   1000034; a distributed filename or source declaration does not establish the
   installed version or embedded assets. Bind the Web resource version to 2c0e277c
   using the existing release readback; a Server-only version is insufficient.
   If it differs, record the mismatch and stop claiming coverage for this target;
   do not install, replace or roll back a package for this audit. If existing tools
   cannot bind the installed signed package/resources to that manifest, keep
   that identity item unverified; the version number alone is not byte identity.

2. **Use a no-charge opportunity.** Prefer an already approved local synthetic
   response/audio environment that exercises the actual automatic-read path.
   Otherwise passively observe the next reply the user was already going to
   request. This handoff does not authorize extra model/TTS requests, replay of
   a completed idle message, voice/format changes, cloning or new configuration.
   The packaged production page has no established local-WAV injection UI; do
   not invent one, enable Web debugging or load an arbitrary test page. With no
   approved fixture or natural operation, leave playback items pending.

3. **Activation and one interruption.** On that reply, verify a text bubble
   rather than an unsolicited audio attachment. When speech actually plays,
   only its bubble should animate. If ArkWeb blocks playback, record the state;
   use the original long-press replay entry only when it resumes the same already
   loaded blocked/paused source. Source code reuses that source, but the actual
   touch gesture and engine acceptance still need observation. If existing UI or
   approved readback cannot distinguish that loaded state from an idle completed
   message, leave the gesture case pending rather than risk a new synthesis.
   Then click the
   playing bubble: sound and its frame must stop promptly, including while text
   continues arriving. Wait for the remaining reply/deltas to finish; old chunks
   must not restart. Existing approved opaque request counters may confirm no
   extra synthesis; without them report only what was observed, not zero calls.

4. **Typing, then retained/recreated view.** On a separate approved fixture or
   next natural reply, start typing one unsent character. Sound/frame must stop;
   clearing the draft must not catch up old chunks. After this explicit stop,
   use the existing task/contact navigation, then the HC owner's agreed native
   Back/background/foreground or lock/unlock step. Record whether the document
   was retained or replaced and whether interrupted audio reappears. A fresh
   normal reply after return should remain eligible, subject to supported
   activation. Do not create an extra paid reply just to complete the case.
   Pure background playback without a prior explicit stop is an observation
   for HC-03/05, not a new policy imposed by this checklist.

For the same observations, note actual pause/end/error frame cleanup and
system reduced-motion/forced-colors behavior if already available. Do not force
production decoder/network failures or change accessibility settings without
the owner's existing plan. Missing variants remain UNVERIFIED. Explicitly
requested audio files are a separate attachment path; their native player is
not evidence for automatic HTMLAudio/MSE playback.

Keep a short record: installed version and manifest identity; operation A/B
(no message text); cold/resumed and native lifecycle action; blocked/loading/
playing/idle/error observations; physical sound stopped or not; active-bubble
count; whether an old queue restarted; and which variants remain untested.
Keep recordings and content private. Native playing/graph events are not
physical acoustic onset, and no numeric latency pass is available without a
valid physical recording and clock/measurement uncertainty.

Do not run parallel field sessions. Preserve drafts, history, old task queues,
permissions and the configured model/voice. If no safe no-charge operation is
available, hand back the exact missing condition instead of manufacturing a
paid sample or asserting a pass.
