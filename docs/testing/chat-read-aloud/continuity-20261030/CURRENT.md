## Concrete local causes and corrections

1. **Automatic trigger**: post-render observation can first see a fast reply already final and baseline it as history. Synchronous live eligibility now precedes DOM text extraction. Original red: zero automatic requests; corrected: one, without replay or reading old history.
2. **Fragmentation and network gaps**: old 80ms/comma/32-character opening flushes repeatedly start synthesis contexts; old ended-before-request scheduling adds network delay. Those forced opening cuts are removed. Sentence punctuation requires textual lookahead or actual final flush; abbreviations, initials, decimal/version/domain dots and numbered labels are protected. The unchanged server 500-rune input cap is the only forced length boundary, not a latency target. MP3 MSE uses the one clock above. WAV/unsupported MSE formats retain full-body compatibility and are not claimed continuous.
3. **Missing text / row ownership**: per-character `**重要。**后续…` can temporarily render a strong sentence and later reclassify the source, invalidating the old spoken prefix and dropping the suffix. Lookahead avoids committing that ambiguous punctuation. Real MarkdownRenderer per-character source coverage now passes for the two retained examples, including final tails and hidden-link exclusion. A second red shows a settled assistant row consuming a different live row sharing a turn/run. Tracking now uses the transcript reconciler's stable render id; turn is retained as context, messageId identifies the exact row for text collection, cache and bubble state. Real history replaceMessages/adoptRenderIdentity retains that id while moving the stored id to serverId. Distinct rows never share the MP3 decoder as one bubble.
4. **Replay charging again**: old replay invokes synthesis. New replay reads EOF-complete encoded bytes from a page-memory cache, bound to current principal/Bot/session/model/turn/render-row/run, normalized visible text version, actual resolved configuration identity and MIME. Tap the consumed stream rather than an unbounded faster tee. Partial/canceled/missing/changed audio cannot silently regenerate. Stop preserves complete bytes; auth/unmount clears this cache without touching server history or attachments. No arbitrary TTL, quota or history cleanup. A read-only GET validates current active-account/Bot permission and voice/model/format identity; it is not a generation request. A blocked/paused *original in-progress operation* is labeled Continue; resuming it can finish its original pending text, distinct from completed cached Replay.

The backend adds only the config GET and the POST's opaque identity header, exposed through existing CORS for the shared client. The GET uses the same account-only JWT/current-account/Bot chat gate; legacy `/tts/synthesize` is unchanged. Identity is computed from the effective resolved configuration, not a client-guessed model/voice id. No secret config is returned. Swagger and SDK were generated normally; [383 existing SDK operation initializers are unchanged](sdk-current-contract.json), with exactly one new GET. One pre-existing handler lint failure (`unused modelID` and `reasoningEffort` arguments) required naming those already-unused parameters `_`; the function call/signature shape and contact resolution behavior are unchanged.
