# Harmony RCP physical endpoint consumer

Contract source: `808cf8010a50b5f7d291221249591d000e7d85aa`, handoff `d1f2c0b943423c5899b18e28b3fd5d9bb56143a1` (`docs/testing/transfer-endpoint-routing/connection-coverage.json`). This change implements only the previously missing native RCP consumer. It does not transplant the Web/Go implementations or change the file protocol, queue, limits, receipt, recovery or SDK endpoints.

## Exact connection point

`NativeResumableUpload.owner` and `NativeMediaDownload.bind` read optional `network_policy` from the existing authenticated logical `/users/me` response, after the original HTTP/owner/lifecycle checks. Missing policy leaves existing behavior unchanged. The internal ArkTS DTO uses exactly the shared fields `version`, optional `lan_addresses`, and `endpoint={logical_origin,physical_origin}`. It is not a new settings document. The existing private deployment seed/parser remains v1 and is not edited; v2 is consumed from the authenticated NAS response.

`NativeTransferNetwork.adopt` snapshots and validates v2 canonical HTTP(S) origins and the logical-origin match. It resets transient address selection when an authenticated route changes. At the final RCP seam, the original factory still executes its lifecycle guard. The assembled method and URL must match the original logical target before its writable SDK `Request.url` receives the physical scheme/host/port. The original path/API prefix, request ID, content/chunk source, headers, destination and tracing callbacks are preserved. No extra buffer conversion or independent file sender is added. HTTP Host and HTTPS SNI belong to the explicitly selected physical destination; system certificate validation remains enabled and redirects are disabled. This is not a Host/SNI impersonation of the logical server.

The logical base still owns the upload owner hash and download journal key. Physical host/port never enters persisted identity, receipt IDs, offsets or file references. An uncertain write is returned to the original receipt reconciler without transport replay. HTTP401/403/404/503 and certificate errors do not trigger another endpoint. Existing v1 LAN-address/IPv6 metadata-read selection remains, including system-proxy and literal-authority behavior. With v2 plus LAN hints for a DNS authority, the existing selector operates on the physical authority; a literal physical destination retains normal platform routing. This does not claim automatic LAN/IPv6 fallback for every literal endpoint.
