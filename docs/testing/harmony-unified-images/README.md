## Browser-confirmed rapid reload defect

After a successful save and quick reload, the existing disk display cache was
fresh but had correctly removed `api_key`. The real form then treated the absent
masked Key as a missing server credential. The reference switch changed its
boolean correctly, but `form.meta.valid` remained false and Save was disabled.
An explicit diagnostic validation returned only the API Key required error.
The failure was not a broken Switch event or reference-policy rejection.

The existing providers query in `models-panel.vue` now uses
`refetchOnMount: 'always'`. It refreshes its ordinary authenticated endpoint even
when the display snapshot is fresh. Secret stripping, write-only Key entry,
server checks and existing save refresh stay unchanged. No new endpoint, cache,
authentication scope or form-validation bypass is added. The existing builder
contains this one guarded adaptation; [the same minimal patch](provider-reload-refresh.patch)
can be applied upstream. There are 44 prior platform seams plus this one seam.
