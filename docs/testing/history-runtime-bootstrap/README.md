## Proven initialization defect

`bootstrap.selectBot(T,{sessionId:S})` has a same-Bot shortcut. A cold page can
restore `currentBotId=T` before `initialize()` has ever started. In that state
there is no `initializePromise` to await and no WebSocket handle. The shortcut
formerly called `selectSession(S)` directly:

1. `startSessionRuntime(T,S)` creates its readiness promise and registers S with
   the real runtime client. That client is disconnected, so it cannot send the
   subscription; this function does not create a socket.
2. Independently, the real views/transcript fetches S's original history.
3. Even after REST resolves, `commitInitialHistory` awaits the initial snapshot.
   Without a target transport, none can arrive through this lifecycle. The
   transcript's owned loading flag stays true and visible messages stay empty.
   The pane's unchanged skeleton condition therefore remains eligible.

A pane-view binding may also have started this same runtime load before Bot
selection. Creating another history request or bypassing the snapshot would
hide the ownership bug. The correction instead supplies the missing transport.

The defect also prevented a synchronous transport setup error from reaching
the route's existing error handling: no connection was attempted at all. This
is separate from asynchronous handshake rejection/reconnect or observer loss,
which are not diagnosed from the field's missing frames.

the same-Bot branch calls the already-existing `ensureWebSocket(T)` before

reconnect behavior. It does not unconditionally close/restart a warm socket.
