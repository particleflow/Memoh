# Opt-in Bot workflow skills

`windows-computer/SKILL.md` is a reusable procedure for authorized Windows command and local-agent work. It contains no device identifiers, endpoints, private paths or credentials. Repository files here are **not automatically installed** into any Bot.

For an individually selected Bot, use Memoh's existing authenticated Skills upload API (`POST /bots/{bot_id}/container/skills`, body `{"skills":["<complete SKILL.md text>"]}`), which requires workspace-write permission. The managed location is `/data/skills/windows-computer/SKILL.md` on that Bot's native Server Workspace, not on the connected Windows computer. The normal skill discovery exposes metadata; `use_skill` loads full instructions on demand. Installing the skill does not configure a target, connector, Pi or Magpie and does not grant access. The skill requires those separate capabilities to be discovered at execution time.

This branch also adds a short code-owned computer-routing contract through `ToolRequiredUsage`. The native runtime injects it only when the execution-location capability is registered, as a separate system fragment with `RetentionRequired`. Ordinary Usage stays Preferred. The short contract requires discovering the authorized PC, keeping Server Workspace tasks/defaults separate, checking the configured agent route, and stopping mutations if full instructions or submission outcome are uncertain. It does not require installing this skill. The detailed Herdr/Pi procedure becomes available only after a deliberate per-Bot installation. Neither change is deployed merely by creating this branch.

Keep real computer roots, Git Bash executable paths, Pi configuration directories, provider endpoints and secrets in private deployment configuration. The instructions use root-relative business paths and current discovery results. Memoh's existing native workspace and authorization checks remain in place; the Agenvo command target remains foreground execution only.

Verify installation with the Bot's skill catalog, then verify activation with a read-only conversation before sending work. Upload success alone does not prove that the model received the instructions: Memoh's existing context-budget selection can prune the detailed skill, including after a successful first load. The protected short contract instructs the model not to guess or repeatedly activate a missing/pruned skill. It remains subject to admission: if required system content cannot fit, the request fails instead of dropping the contract. There is no skill `priority` or `protected` metadata switch. Use the actual model's supported context configuration; the 32K/64K validation cases are pressure fixtures, not model limits or deployment settings.
